Read the AskTD delivery Stories from Jira and draw their dependencies as one diagram. Read only: write nothing to Jira.

Limits
- Use the existing Jira connection of this workspace, with read requests only. Never display a token, the Jira address, a full URL, a request header or a response body, and never open, view or list an environment file.
- No person's name in any file or answer. For the owner of a Story, use the role on its "Owner" line.
- Python standard library only; no install and no download. Write every file into a new folder asktd-deps/ beside your import ledger, outside the planning package.

1. Read every issue in project ASKTD with the label asktd-delivery: key, summary, status, priority, labels, the marker on the first line of the description, and the description. Leave out the issues with the label asktd-known-limitation and only count them.

2. Find the dependencies in the section "Depends on." of each description.
- A delivery Story is named there by its id (S1-04, S2-10, F-03 and so on), often with its key. Map ids to keys through the markers.
- A planning Story is named by its title and key.
- Everything else in that section is an outside prerequisite, for example a merge, a file, a decision, a person or a team. Give each one a short name, and merge the ones that mean the same.
- Where the section says that the work can start before a dependency is met, mark that dependency as soft.
- Also use Jira links of a blocking type, if there are any. A "Relates" link is not a dependency.

3. Check for dependency cycles; for a Story in Sprint 1 or Sprint 2 that depends on a Story in a later column; and for Stories that depend on nothing, which can start now.

4. Draw the diagram as one self-contained HTML file with an inline SVG, asktd-deps/dependency-map.html, with no script, no external file and no network.
- Columns from left to right: outside prerequisites and planning Stories; Sprint 1; Sprint 2; after the January demo; not placed. Take the column from the labels asktd-sprint1-candidate, asktd-sprint2-candidate, asktd-later-candidate and asktd-unscheduled.
- One box for each Story: key, id, a short title, owner role and status. Fill by status: to do grey, in progress blue, done green. A thick border for priority High.
- An arrow from each prerequisite to the Story that needs it: solid for a hard dependency, dashed for a soft one, red for a timing conflict of step 3.
- In each column, put prerequisites above the Stories that need them, and keep crossing arrows to a minimum. Add a legend. The text must be readable on a normal screen without zooming.
Also write asktd-deps/dependencies.md: one table row for each dependency (from, to, hard or soft, conflict yes or no), then the Mermaid source of the same graph.

5. Open the HTML file in the default browser.

Then show me, in at most 15 lines: the number of Stories read and left out; the number of dependencies; the Stories that can start now; each outside prerequisite with the number of Stories that wait for it; each timing conflict and each cycle in one line. Stop there.
